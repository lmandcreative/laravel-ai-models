# Laravel AI Models 2.0.0

**Built for the Laravel AI SDK 1.x.**

2.0 moves `lmsomeco/laravel-ai-models` onto `laravel/ai` 1.x. It now
resolves providers through the SDK itself rather than by reading raw config
arrays, and that brings four headline features:

- list models for **any SDK provider**, including ones built on demand;
- know **which model the SDK uses for what**;
- handle listing failures with the **same exceptions as a failed prompt**;
- connect **self-hosted OpenAI-compatible servers**.

> **This is a major release with breaking changes.** It requires
> `laravel/ai` ^1.0.1. Most apps need two edits: read `$model->driver` where
> they used `$model->provider` as a `Lab`, and update a published
> `config/ai-models.php`. Start with the **[upgrade guide](https://github.com/lmandcreative/laravel-ai-models/blob/v2.0.0/UPGRADE.md)**
> (about 10–30 minutes).

```bash
composer require lmsomeco/laravel-ai-models:^2.0 laravel/ai:^1.0.1 -W
```

## Highlights

### Model roles: which model does the SDK use?

Every listed model is now tagged with the roles its provider assigns it. The
roles are read straight from the SDK provider, so they honour your
`models.*` overrides in `config/ai.php`:

```php
use LmSomeco\AiModels\Enums\ModelRole;
use LmSomeco\AiModels\Facades\AiModels;

AiModels::default('openai');                              // the SDK's default text model
AiModels::default('anthropic', ModelRole::CheapestText);  // its cheapest text model
AiModels::default('openai', ModelRole::Embeddings);       // its default embeddings model

$model->roles;                       // [ModelRole::Text, ModelRole::SmartestText]
$model->is(ModelRole::CheapestText); // bool
```

The roles are `Text`, `CheapestText`, `SmartestText`, `Image`, `Embeddings`,
`Audio`, `Transcription`, `Reranking` and `Classification`. They're applied
after the cache read, so changing a default never needs a cache refresh. A
model picker can now pre-select the model your agents would use anyway.

### List models for any SDK provider, including `Ai::build()`

`AiModels::provider()` now accepts any laravel/ai `Provider` instance, not
just a config name. Per-tenant keys, admin-managed keys and bring-your-own-key
setups can list models without ever touching `config/ai.php`:

```php
use Laravel\Ai\Ai;

AiModels::provider(Ai::build([
    'name' => "tenant-{$tenant->id}",
    'driver' => 'anthropic',
    'key' => $tenant->anthropic_key,
]));
```

### Database connectors are real SDK providers

`ConnectorManager::provider($connector)` builds an on-demand laravel/ai
provider named `db-{id}` using `Ai::build()`. It no longer mutates
`config('ai.providers')`. The provider serializes with its key **encrypted**,
so it can go into queued agents. Return it from an agent's `provider()`
method and every prompt uses the connector's credentials:

```php
public function provider(): Provider
{
    $manager = app(ConnectorManager::class);

    return $manager->provider($manager->resolve($this->connectorId));
}
```

### Failures raise the SDK's own exceptions

Listing errors are mapped with the SDK's own failover logic, so a
rate-limited model listing is handled exactly like a rate-limited prompt:

| Failure | Exception |
|---------|-----------|
| Connection failure / timeout | `ProviderConnectionException` |
| HTTP 429 | `RateLimitedException` |
| HTTP 402 | `InsufficientCreditsException` |
| Transient 5xx (plus Anthropic 529, Groq 498) | `ProviderOverloadedException` |

All four extend `Laravel\Ai\Exceptions\AiException`. `php artisan ai:models`
now reports them as a clean one-line error instead of a stack trace.

### Self-hosted OpenAI-compatible servers

The SDK's `openai-compatible` driver is supported out of the box. That covers
vLLM, LM Studio, LiteLLM and anything else serving an OpenAI-style
`/models`. Set `OPENAI_COMPATIBLE_URL`; a key is optional.

### Provider name vs. driver

`AiModel::$provider` is now the provider's **name** (`openai`, `openai-eu`,
`db-5`, ...), and the new `AiModel::$driver` holds the `Lab`. Models from two
providers on the same driver, such as your `openai` entry and a database
connector pointing at OpenAI, can finally be told apart. The `ai:models`
table gains **Driver** and **Roles** columns.

## Breaking changes

Each item links to its section in the [upgrade guide](https://github.com/lmandcreative/laravel-ai-models/blob/v2.0.0/UPGRADE.md).

- **Requires `laravel/ai` ^1.0.1.** 0.x is no longer supported.
  ([details](https://github.com/lmandcreative/laravel-ai-models/blob/v2.0.0/UPGRADE.md#laravelai-101-is-required))
- **`AiModel::$provider` is now a provider name (`string`).** The `Lab` moved
  to `AiModel::$driver`, and `toArray()` / `--json` gained `driver` and
  `roles`. ([details](https://github.com/lmandcreative/laravel-ai-models/blob/v2.0.0/UPGRADE.md#aimodelprovider-is-now-the-provider-name))
- **Resolver config entries use `resolver` instead of `driver`.** A published
  1.x `config/ai-models.php` must be updated or re-published.
  ([details](https://github.com/lmandcreative/laravel-ai-models/blob/v2.0.0/UPGRADE.md#resolver-config-uses-resolver-instead-of-driver))
- **`ConnectorManager::configure()` was removed.** Use `provider()`.
  ([details](https://github.com/lmandcreative/laravel-ai-models/blob/v2.0.0/UPGRADE.md#connectormanagerconfigure-was-removed))
- **`ModelRegistry::driver()` and `ModelRegistry::connector()` were removed.**
  Use `provider(Ai::build([...]))` and `ConnectorManager::models()`.
  ([details](https://github.com/lmandcreative/laravel-ai-models/blob/v2.0.0/UPGRADE.md#modelregistrydriver-and-connector-were-removed))
- **`Connector::getProvider(): string` is now `getDriver(): Lab`.** Models
  using `IsConnector` or extending `AiConnector` are unaffected.
  ([details](https://github.com/lmandcreative/laravel-ai-models/blob/v2.0.0/UPGRADE.md#connectorgetprovider-is-now-getdriver-lab))
- **The resolver contract changed:** `provider()` returns the SDK `Provider`,
  and resolvers are built with `(HttpFactory, Provider, array $config)`.
  `$config` no longer carries credentials, and the shipped resolvers extend a
  new `Resolver` base class with a `final` `models()`.
  ([details](https://github.com/lmandcreative/laravel-ai-models/blob/v2.0.0/UPGRADE.md#custom-resolvers))
- **Constructor changes** to `AiModel`, `ModelRegistry` and
  `ConnectorManager`. ([details](https://github.com/lmandcreative/laravel-ai-models/blob/v2.0.0/UPGRADE.md#constructor-changes))
- **HTTP failures** throw laravel/ai exceptions instead of
  `RequestException` / `ConnectionException` (429, 402, transient 5xx and
  connection errors). ([details](https://github.com/lmandcreative/laravel-ai-models/blob/v2.0.0/UPGRADE.md#listing-failures-throw-laravelai-exceptions))
- **Cache keys are versioned** (`ai-models:v2:{name}`), and connectors are
  cached under `db-{id}`. Expect one fresh fetch per provider after deploying.
  ([details](https://github.com/lmandcreative/laravel-ai-models/blob/v2.0.0/UPGRADE.md#cache-keys-changed))

## Fixes

- A `config/ai.php` entry whose `driver` is a `Lab` case
  (`'driver' => Lab::OpenAI`) is no longer silently ignored.
- Providers on the same driver no longer produce indistinguishable models.
- Provider entries without a `driver` key are skipped cleanly.

## Requirements

| | 1.x | 2.0 |
|---|---|---|
| PHP | 8.3+ | 8.3+ |
| Laravel | 12, 13 | 12, 13 |
| `laravel/ai` | 0.7 – 0.11 | **1.0.1+** |

Tested against `laravel/ai` 1.0.1 and the latest 1.x, on PHP 8.3/8.4 and
Laravel 12/13.

## Upgrading

1. Upgrade `laravel/ai` to 1.x using
   [its upgrade guide](https://github.com/laravel/ai/blob/1.x/UPGRADE.md).
2. `composer require lmsomeco/laravel-ai-models:^2.0 laravel/ai:^1.0.1 -W`
3. Follow the **[2.0 upgrade guide](https://github.com/lmandcreative/laravel-ai-models/blob/v2.0.0/UPGRADE.md)**. It includes a
   checklist, search commands to find affected code, before/after examples
   and a troubleshooting table.

No database migrations are needed. The `ai_connectors` table is unchanged.
